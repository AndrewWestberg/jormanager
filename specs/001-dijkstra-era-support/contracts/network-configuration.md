### ManifestV1 wire format and identities

The normative [JSON Schema draft 2020-12](network-configuration.schema.json) defines the complete `ManifestV1` wrapper `{resetId, bundleId, payload}`. All properties at every level are required; unknown properties and implicit defaults are forbidden. Reject duplicate object member names at every level **before** parsing can discard duplicates. Validate using a draft 2020-12 implementation with `format` assertions enabled, not annotation-only: `retrievedAt` must be a valid UTC calendar timestamp in exactly `YYYY-MM-DDTHH:mm:ssZ` form and `sourceUrl` an absolute HTTPS URI with a nonempty host. Require functioning `date-time` and `uri` assertion support; a configuration flag alone is insufficient when optional validator dependencies are absent. Probe rejection of an invalid calendar date and malformed URI rather than silently accepting unknown formats. Reject invalid Unicode or other inputs that cannot be canonicalized by RFC 8785.

The exact payload is `{schemaVersion, identity, assets, retrievedAt, provenance}`:

- `schemaVersion` is integer `1`. `identity` is exactly `{networkMagic, systemStart, genesisHashes}`: `networkMagic` is an unsigned 32-bit integer; `systemStart` is a canonical nonnegative decimal epoch-second string (`0` or a nonzero digit followed by digits, with no sign or leading zeroes); `genesisHashes` maps exactly `byron-genesis.json`, `shelley-genesis.json`, `alonzo-genesis.json`, `conway-genesis.json`, and `dijkstra-genesis.json` to lowercase 64-hex-digit node-required genesis hashes.
- `assets` maps exactly those five names plus `config.json`, `topology.json`, and `peer-snapshot.json` to `{sha256, sourceUrl}`. Each `sha256` is the lowercase 64-hex-digit SHA-256 of the raw asset bytes. `sourceUrl` is an absolute HTTPS URI with a nonempty host, no userinfo and no fragment; preserve its exact encoded string when hashing, without URL normalization. It records upstream provenance, not permission to fetch from that URL.
- `retrievedAt` is the publisher's upstream snapshot time, not the consumer's fetch time. `provenance` is exactly `{release, components}`, where `release` is a nonempty string or null, and `components` is exactly `{node, cli}`. Each component is exactly `{version, revision, binarySha256}`: version and revision are each nonempty strings or null; binarySha256 is lowercase 64-hex-digit SHA-256 or null. Null provenance is not evidence of support or qualification. A separate runtime manifest records dependency identities and qualified capabilities; do not introduce local version pins.

Compute `resetId` as lowercase hex SHA-256 of the UTF-8 bytes of RFC 8785 JSON Canonicalization Scheme (JCS) serialization of `payload.identity`. Compute `bundleId` identically over `payload` in its entirety. Hash exactly the JCS bytes, with no BOM or added newline. The wrapper IDs and published prefixed filenames are outside both hash inputs; all payload values, including the publisher's `retrievedAt` and source URLs, participate in `bundleId`. Preserve full IDs, reject mismatches or conflicting content, and use shortened labels only for display.

The shared [synthetic ManifestV1 vector](../../../src/test/resources/dijkstra/network-manifest-v1-vector.json) is a serialization and hashing vector only, not an actual network fixture or qualification evidence. Its eight SHA-256 values are for the two raw bytes `{}` without a newline; its zero genesis hashes and those bytes deliberately do not form valid ledger genesis assets. Do not promote or deploy it as a bundle.

Distinguish raw-byte SHA-256 asset digests from the genesis hash algorithms required by the node. Before promotion, compute each genesis asset's node-required hash using qualified tooling and require it to match both the corresponding `identity.genesisHashes` value and configured node hash; validate cross-references, magic and system start as well. Schema validity and matching wrapper IDs alone do not prove ledger validity. Fetch only through the configured trusted HTTPS catalog origin with certificate verification; do not accept arbitrary caller download origins or redirect trust to an unapproved host. A manifest `sourceUrl` is provenance only and does not authorize fetching. The publisher records the upstream source snapshot and the release maintainer independently compares served bytes to it. Manifest hashes detect partial/mixed/changed files but do not protect against a compromised authorized publisher; the existing catalog's trusted-publisher assumption remains explicit, without introducing a new signing service or claiming TLS proves ledger compatibility.

Implement ingestion as a complete, validated bundle snapshot: check successful HTTP responses, parse expected files, verify provenance/digests and internal references, then atomically make the bundle selectable. A failed download, malformed asset, bad hash, missing peer snapshot, partial publication, duplicate basename or cross-reset mixture must leave the prior selectable bundle intact and block the new one with an actionable error. Store immutable content snapshots and provenance associated with each created node, not mutable `File` rows overwritten by periodic refresh. A poll can discover a later bundle but must not modify an existing node, chain database, configuration, or cached genesis through shared IDs.

Observed catalog config points to all five `musashi-<era>-genesis.json` files, and topology points to `musashi-peer-snapshot.json`. These source references resolve successfully. When JorManager writes unprefixed local filenames, rewrite all five genesis references and the peer snapshot reference together, validate the resulting paths, and record source versus effective digests; normalizing only the first four genesis files leaves the producer/relay unusable.

   Before the new node exists, initialize target-network current-era evidence by querying an already connected verified observer/reference node with matching network identity; record source/point/time. 4. Create a new producer (`core`) on a clean managed host/directory or use a supported pool-child arrangement only after proving parent and credentials behavior on this bundle. ## Reset and qualification

If any genesis identity or system start changes, treat it as a new reset, even if magic 164 is reused. Mark old network data stale and disable dependent spending/registration until the operator explicitly chooses the new bundle and a clean node/database and replay or supported recovery path. Never silently join old state, credentials, pending authorizations, wallet balances or pool activation to the new chain. A topology-only update is also a new bundle; applying it to an existing node requires explicit review and verification rather than polling side effects. Retain old snapshot and evidence needed for audit/restore; do not erase operator data automatically.

Qualification must demonstrate publication through the actual catalog, complete download and selection, independent digest/genesis checks, clean relay sync, and new producer/pool creation, registration and observed startup. Add negative cases for mixed/missing/tampered assets, concurrent partial publication, unreachable server, stale selection after reset, unsupported CLI/node and missing BLS startup capability, and prove no remote write/signing occurs before preflight. Test documented role overrides and both managed startup mechanisms; use a private same-bundle network for controlled failure, reset and epoch scenarios. Public Musashi starts Dijkstra at epoch 0. See [quickstart](../quickstart.md), [evidence manifest](evidence-manifest.md), and [operator messages](operator-messages.md).
