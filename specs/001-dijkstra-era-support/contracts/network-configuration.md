# Network configuration and provisioning contract

Musashi is the Dijkstra qualification baseline, not a configuration publication protocol. Use ordinary file options, including downloaded catalog files or operator-imported files. Select Byron, Shelley, Alonzo and Conway genesis, config and topology individually; select Dijkstra genesis and peer snapshot when the chosen config or topology references them. Dijkstra and peer selections are optional and clearable for Conway. No manifest, bundle identity, publication protocol, reset handling or replacement workflow is required. Operators own network resets and resynchronization; catalog refresh must not mutate existing nodes.

Before remote effects, resolve selected files by ID and validate strict JSON (including duplicate keys and trailing input), all required references, configured genesis hashes including canonical Byron, network magic and system start consistency and peer magic when present. Reject missing, corrupt, mismatched or incompatible files actionably. Install standard local basenames and normalize topology's peer snapshot reference without discarding unrelated settings. Protect existing target data; validation failure must not write remotely or imply readiness.

When config references `CheckpointsFile`, resolve the existing matching `-checkpoints.json` catalog file and include `checkpoints.json` in installed assets. Do not assume a fixed number of files. Migration 046 renames historical `nodes.configuration_reset_id` to `network_key_discriminator`, a hidden, read-only serialization value that preserves existing indexed network keys and their ledger/operations. New standalone selections generate no reset ID and use null, serialized as `-`; a new producer on an existing network copies its observer's opaque discriminator. It is not a reset workflow or public alias. Historical data is retained; old migrations are not rewritten.

A first relay can be created without an existing node or observer. Validate host, path, port and credentials as usual; neither selected files nor a binary version establish the current era. Current-era-dependent writes use the verified matching-network node-derived cache, including block-mismatch refresh and pending/unavailable blocking.

Producer/core/pool workflows require reviewed authorization, a connected matching observer, matching genesis identity and operation-specific capabilities. Choose Conway or Dijkstra from observed current era, not file presence. Pool children inherit their parent's configuration and genesis, including optional Dijkstra, topology and peer files. Preserve existing local source/effective installation snapshots, BLS/bulk validation, credential protection and explicit deployment review; later deployment uses saved bytes, not a catalog lookup. Distinguish installation, start, sync, registration, confirmation, eligibility and loaded-key observation.

Conway and earlier supported networks remain operational without Musashi, Dijkstra genesis or Leios credentials. Independent disposable-host/node/CLI/SSH and browser qualification remains pending; no local smoke or catalog availability proves real synchronization, registration or release readiness.
